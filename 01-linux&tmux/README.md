# 🐧 ДЗ #01: Linux & Tmux — Управление веб-серверами

## 📋 Условие задачи

Необходимо написать консольную программу `homework`, которая управляет набором запущенных копий веб-приложения на Python (`server.py`). Программа должна работать с tmux-сессиями, создавать бэкапы и собирать результаты работы серверов.

---

**Функционал вашей программы**

**1. Запустить новую копию веб-сервера**
```shell
./homework start --name <server_name> --port <server_port>
```
где:
- `<server_name>` — уникальное имя новой копии сервера;
- `<server_port>` — порт, на котором нужно запустить новую копию сервера.
Уникальное имя состоит исключительно из букв в нижнем регистре длиной от 1 до 32 символов.
Запуск новой копии сервера состоит в следующем:
1. Создать в текущей папке новую папку с именем `<server_name>`.
2. Скопировать в созданную папку файл веб-приложения `server.py`. Он будет находиться в той же директории, из которой будет запускаться ваше приложение.
3. Запустить копию веб-приложения **в созданной папке внутри tmux-сессии с именем `homework` в отдельном tmux-окне** с именем `<server_name>` следующим образом:
```shell
python server.py --port <server_port>
```

Копия должна быть запущена именно из своей папки!

4. **stdout** процесса сервера нужно перенаправить в файл `out.txt` в созданной папке — это будет результатом работы веб-приложения.
Примечание: порядок аргументов `--name <server_name>` и `--port <server_port>` может быть произвольный.

**Для продвинутого потока**

Дополнительно нужно реализовать проверки:
1. Если существует копия сервера с именем `<server_name>` — `exitcode 1`.
2. Если существует копия сервера с портом `<server_port>` — `exitcode 2`.
3. Если порт `<server_port>` занят процессом, отличным от сервера — `exitcode 3`.
4. После выполнения команды для запуска копии сервера подождать 3 секунды и проверить его работоспособность с помощью запроса:
```
http://localhost:<server_port>/healthcheck
```

Если ответ имеет статус-код, отличный от 200, то вывести этот статус-код в stderr в формате:
```
Bad response code: <response_code>
```
а также завершить работу с `exitcode 4`.

---

**2. Остановить копию веб-сервера по имени**
```shell
./homework stop --name <server_name>
```
где `<server_name>` — уникальное имя копии сервера, который нужно остановить.
В результате выполнения этой команды:
Процесс копии веб-сервера должен перестать работать.
Содержимое файла `out.txt` останавливаемого сервера должно быть перенесено в отдельную папку `.backup` — соседнюю по отношению к папке с сервером — и названо:
```
out_<server_name>_<stop_timestamp>.txt
```
где `<stop_timestamp>` — timestamp в момент остановки копии.

Примечание: timestamp будет проверяться приблизительно.
3. Tmux-окно этой копии должно быть закрыто.
4. Папка этой копии должна быть удалена.
5. Никакие другие копии не должны быть затронуты.

---

**3. Остановить все копии веб-сервера**

```shell
./homework stop_all
```
В результате выполнения этой команды:
1. Все процессы копий должны быть остановлены.
2. Tmux-окна всех копий должны быть закрыты.
3. Tmux-сессия `homework` должна быть закрыта.
4. Содержимое файлов `out.txt` должно быть забэкаплено — см. выше.
5. Все папки копий должны быть удалены.

---

**4. Сбор результатов работы всех копий**

```shell
./homework collect_all
```
В результате своей работы каждая копия сохраняет свои результаты в файл `out.txt` в своей директории.
Вам необходимо собрать и вывести содержимое файлов `out.txt` всех активных копий, отсортированное по имени копии лексикографически.

Например:
- сначала всё содержимое копии `a`;
- затем копии `ab`;
- затем копии `b`;
и т. д.

Формат вывода:
```
=== server: a ===
<содержимое a/out.txt>

=== server: ab ===
<содержимое ab/out.txt>

=== server: b ===
<содержимое b/out.txt>

...
```

Дополнительно ваша программа должна поддерживать опцию --zip, которая вместо вывода в stdout будет собирать все файлы:
```
<server_name>/out.txt
```
и упаковывать их в ZIP-архив с именем:
```
out_<collect_timestamp>.zip
```
Внутри архива файл с именем:
```
out_<server_name>.txt
```
должен иметь такое же содержимое, как и файл:
```
<server_name>/out.txt
```
При этом исходные файлы `<server_name>/out.txt` должны остаться неизменными!

**О языке и зависимостя**
Саму программу можете писать либо на **Bash**, либо на **Python 3.12**.
**Важно**
Если ваше решение требует дополнительные зависимости — системные пакеты или библиотеки — необходимо указать команды для их установки в скрипте `install.sh`.
**Полезные советы**
- **libtmux** — библиотека Python для работы с tmux. В среде проверки будет установлена версия `0.46.2`.
- **argparse** — библиотека для парсинга аргументов командной строки.
- **click** — альтернатива `argparse`. В среде проверки будет установлена версия `8.3.0`.
- Можете создавать файлы и папки для получения желаемого результата в рамках разумного.
