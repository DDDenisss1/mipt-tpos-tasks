## 🎓 Чему я научился

Реализация этого проекта позволила мне глубоко погрузиться в практики контейнеризации и создания отказоустойчивых распределенных систем. Вот ключевые навыки и концепции, которые я освоил:

### 🔷 Оркестрация многоконтейнерных приложений (Docker Compose)
- Научился проектировать **user-defined bridge networks** для изоляции сервисов и встроенного DNS-резолвинга (обращение к БД по имени сервиса `db`).
- Освоил продвинутые условия зависимостей: `depends_on` с `condition: service_healthy` (для БД) и `condition: service_completed_successfully` (для oneshot-скрипта filler).
- Понял разницу между **named volumes** (для персистентности данных БД между перезапусками) и **bind mounts** (для динамической подмены `data.csv` без пересборки образа).
- Научился правильно настраивать политики перезапуска (`restart: unless-stopped` для долгоживущих сервисов и `restart: "no"` для задач заполнения).

### 🔷 Построение оптимальных Docker-образов
- Освоил использование базовых образов `python:3.12-slim` как баланса между размером образа и совместимостью (в отличие от проблемных `alpine` с C-библиотеками).
- Научился оптимизировать среду Python в контейнере через переменные окружения: `PYTHONDONTWRITEBYTECODE=1` (экономия места) и `PYTHONUNBUFFERED=1` (мгновенный вывод логов).
- Понял важность минимизации слоев в Dockerfile и использования `--no-cache-dir` при установке pip-пакетов.

### 🔷 Надежность и отказоустойчивость (Resilience)
- Реализовал **retry-логику** с таймаутами как на стороне скрипта заполнения (30 попыток), так и на стороне веб-сервера (10 попыток), чтобы gracefully обрабатывать временную недоступность сети или БД.
- Научился настраивать **Docker Healthchecks** (используя встроенный `healthcheck.sh` MariaDB) для объективной оценки готовности сервиса, а не просто факта запуска процесса.
- Освоил возврат корректных HTTP-статусов (например, `503 Service Unavailable` при сбое БД) вместо падения приложения с `500 Internal Server Error`.

### 🔷 Работа с базами данных из Python (PyMySQL)
- Научился использовать `DictCursor` для получения результатов запросов в виде словарей, что идеально ложится на JSON-сериализацию в Flask.
- Освоил **явное управление транзакциями**: отключение `autocommit`, использование `commit()` после успешной пакетной вставки и гарантированный `rollback()` в блоке `finally` при любой ошибке.
- Реализовал **идемпотентность** операций: проверка существования записи (`SELECT 1 ... LIMIT 1`) перед `INSERT`, что позволяет безопасно перезапускать скрипт filler без создания дубликатов.

### 🔷 Строгая валидация и обработка данных
- Научился безопасно читать CSV-файлы с использованием `encoding="utf-8-sig"` для корректной обработки BOM (Byte Order Mark).
- Освоил построчную валидацию данных с информативными сообщениями об ошибках (указание номера строки `line_number`), что критически важно для отладки.
- Понял важность строгой типизации на входе (принудительное приведение `age` к `int` с перехватом `ValueError`).

### 🔷 Разработка веб-сервисов (Flask)
- Научился создавать гибкие API с несколькими алиасами маршрутов (`/`, `/data`, `/api/data`), обслуживаемыми одной функцией.
- Освоил создание выделенных **health-check endpoint'ов** (`/health`), которые проверяют не только работу веб-сервера, но и способность установить соединение с базой данных.

### 🔷 DevOps-культура и Best Practices
- Понял важность **разделения кода и конфигурации**: вынес все чувствительные данные и настройки в `.env` файл, который не попадает в систему контроля версий.
- Научился писать решения, **готовые к автоматическому тестированию**: использование bind mount для `data.csv` позволяет проверяющему подменить файл без необходимости модифицировать или пересобирать мой Docker-образ.
- Освоил написание **самодокументирующегося кода** через осмысленные имена переменных, обработку исключений и структурированные логи (`flush=True`).
